# Ficshon Beta Scope & Core Loop

## Core Product Loop

Ficshon is built around the loop:

Create → Publish → Interact → Continue the story

Every beta feature must strengthen at least one part of this loop.

---

## Day-1 Must-Be-Strong Features

### Character Creation + Identity Lock
This is Ficshon's primary differentiator.

Must feel:
- smooth
- visually impressive
- consistent across generations
- fast enough to feel responsive

---

### Scene Image Generation
Must feel:
- tightly tied to character identity
- simple to trigger
- visually strong
- reliably saved
- easy to use in posts

---

### Posting + Timeline UX
Must feel:
- clean and readable
- balanced visually
- focused on writing, not noise
- easy to follow stories

---

### Realms Discovery + Participation
Must feel:
- understandable immediately
- easy to join
- clearly themed
- socially meaningful

---

### Messaging System
Must feel:
- stable
- familiar
- fast enough
- predictable

---

### Image Library
Must feel:
- reliable
- organised
- easy to reuse images

---

### Writer Workspace (Included Day-1)
Must feel:
- better than a social text box
- distraction-free
- safe (auto-save)
- readable formatting

Minimum requirements:
- headers
- italic/bold
- clean fonts
- basic layout control

---

### Story Generator (Included Day-1)
Must feel:
- guided, not random
- user-controlled
- chapter-aware
- narratively coherent

It does not need deep lore memory yet.
It just needs to feel smarter than typical generators.

---

## Features That Only Need To Work

- Audio generation
- Video generation
- Emoji system (starter set)
- Font choices (small curated set)

---

## Explicitly Out Of Beta Scope

- Monetisation systems
- Creator payouts
- Advanced analytics
- Mobile apps
- Recommendation engines
- Deep moderation dashboards
- Complex search
- Enterprise scaling work
- Full brand redesign

---

## Beta Success Criteria

A new user should be able to in one session:

1. Create a character
2. Generate images
3. Write something
4. Join a realm
5. Interact with someone

Users should return because:

- they want to continue a story
- someone responded to them
- they want more scenes
- they want to improve their character
- they want to write again

---

## Day-1 Experience Goal

A new user should feel:

"I can create a character, write a story, generate scenes, and share it with people who actually care about stories."
